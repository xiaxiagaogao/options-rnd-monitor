## 2. 标的池约束（现行）

来源：`symbols.yaml` + spec。

- **固定 3**：SPY / QQQ / NVDA  
- **动态 2**：准入检查后换入，回填约 1–3 小时  
- 换出 **不删** 历史链数据  
- 月度到期、DTE 7–60、钉最近两个月度  

任何「同步真实持仓」方案必须尊重：**同时可计算/可展示的 RND 标的数有上限（当下 3+2）**，不能默认「券商里有什么就全画 RND」。

## 3. 新条件 · 持仓双轨（2026-07-23 补充）

### 3.1 现状

| 系统 | 持仓来源 | 能力 |
|------|----------|------|
| **本 RND 仪表盘** | **手动** 录入入场 / 平仓（`trade_journal` 冻结分位线） | 与 RND 分位、冻结 Q05/Q25、偏移 σ 深度绑定 |
| **另一券商仪表盘** | **实时** 连券商账户 | 多标的、开仓时间、敞口大小等；**无** 本仓库 RND 五表语义 |

### 3.2 用户前瞻需求

1. 可能需要 **同步实时持仓** 到 RND 侧  
2. 同步后对持仓标的 **抓期权链 / 算 RND**（受 3+2 池限制）  
3. 券商侧标的集合 **⊇** RND 池；多数标的可能长期只有持仓摘要、无 RND 图  

### 3.3 设计含义（决议倾向，未实施）

**A. 双轨并存，不立刻砍手动日志**

- **券商轨**：真相源（有什么仓、多大、何时开）  
- **RND 轨 / journal**：研究语义（冻结哪条分位、信念 vs 投机、失效是否触发）  
- 自动同步可以 **预填** journal，但「冻结哪条 Q」仍需要规则或确认，不能静默当成已研究结论  

**B. 池与持仓解耦**

```
券商持仓列表（N 只，可很大）
    ↓ 映射 / 筛选
RND 计算池（≤ 5 = 固定3 + 动态2）
    ↓
深页图 + 状态条 + 助手上下文
```

- 池外持仓：总览可显示「有持仓但未入 RND 池」  
- 入池：走现有准入 + 回填，或「从持仓一键申请入池」  
- **禁止** 假设实时同步 = 无限扩池  

**C. 导航与持仓的关系（呼应 §1）**

| 页面 | 持仓怎么用 |
|------|------------|
| 今日 `/` | 展示 **券商+journal 合并摘要**（敞口、是否在池、是否有冻结线） |
| 标的 `/sym` | 仅 **当前 RND 标的** 的冻结线与图；状态条属此页 |
| 助手 | 问句可带持仓上下文；标的仍受池与数据是否就绪约束 |

**D. 同步接口（占位，未选型）**

后续需单独决策，本档只锁约束：

- 拉取频率：EOD 对齐 vs 盘中（本产品主路径仍是 EOD）  
- 字段最小集：`symbol, side/qty or notional, open_time, account_id?`  
- 与 `trade_journal` 的主键策略：外部 id vs 本地 position_id  
- 密钥与部署：不得进前端；仅服务端  

### 3.4 明确非目标（当前）

- 不在本阶段实现券商 OAuth / 同步管线  
- 不把 RND 仪表盘改成交易执行端  
- 不取消 3+2 池上限来「迁就持仓数量」
